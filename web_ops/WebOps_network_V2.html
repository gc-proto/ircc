StationA stage of the work: intake, triage, design, check, launch, monitor.
LineA route type. It decides which stations the work stops at. Triage picks it.

Journey planner

This is triage. Answer the triager's questions and the ticket shows the line, the priority, every stop and who works there, plus what to record in Asana. Or start from a line and pick one of its example trips.

Network map

Each line is a route type. A ring is a stop; a line running past a station without a ring skips it. The shaded zones are the loop's three poles, and launch is the interchange between design and measurement. The yellow loop line brings discovered work back to triage.

When does a trip need Enterprise?

  • A design that differs from existing templates and components
  • Content driven by data files behind the page, such as JSON
  • Interactivity: tools, wizards, calculators, filters, dynamic content
  • A new template or component, or a link to another system (DPM, APIs)

Any of these puts the trip on the Custom build line (or New pattern, if other pages will reuse it). Otherwise Publishing builds it on the Express line.

Crew roster

What each role does at each station. Duties on the current ticket are highlighted and numbered in the order of the stops.

Network services

The regular services that keep the network running and find the next trips. Select a service to see what it is, who runs it, how it runs, and how to use it.

    Weeks are counted within each quarter. Timings are proposals to set with the team.

    Objectives

    WebOps OKRs for FY 2026–27, one objective per part of the network, and the team OKRs that feed them. Each key result links to the station, line or network service that moves or measures it. Q3 is October to December 2026; Q4 is January to March 2027.

    Shaded numbers are placeholders to set with the team. Many Q3 targets are baselines: an honest target needs a quarter of data first.

    Triage rulebook

    The criteria behind the journey planner. Numbers in dashed boxes are placeholders to set with the team, and the priority section should be reconciled with WebOps' existing P1 to P3 definitions.

    Draft for discussion. Builds on the WebOps operating model, the performance framework and the RAD team's three poles. Line names, timings and thresholds are proposals.
